Structural Navigation

Structural navigation comes in several forms, each scoped to a different level of the information architecture. Global navigation links to the home page and the main pages of major sections, providing consistent, universal access and orienting people to the site's key topics. Local navigation operates within a specific section, showing where someone is within that particular part of the site rather than the whole space. Universal navigation shows up in large enterprises with multiple subsites, connecting those related subsites back to one shared, top-level home page. And contextual navigation operates at the smallest scale of all — page-specific links, often anchor links, that let someone jump directly to a subsection of the single page they're already on.

Despite their different scopes, all four types need to behave consistently — the same visual conventions for indicating state and current location — so that someone who's learned how one type works can immediately understand the others.

Global navigation answers "what parts does this whole site have." Contextual navigation answers "what parts does this one page have." They're doing the same fundamental job at wildly different scales.

Exercise

The scenario: A large enterprise software company's support portal exists as a subsite within a larger corporate website. Four navigation elements appear across the portal's pages.

1. A thin bar at the very top of every page, above the support portal's own header, linking back to the main corporate site's home page and its other major properties.
2. The support portal's own primary navigation bar, linking to its main sections — Documentation, Community Forums, Contact Support, Downloads.
3. Within the Documentation section specifically, a sidebar listing subsections like "Installation Guides," "API Reference," and "Troubleshooting," visible only while browsing within Documentation.
4. On a single long API Reference page, a small "Jump to" list of anchor links pointing to specific subsections further down the same page.
Chunk complete
Feedback

1 — Universal navigation. A bar connecting a subsite back to the larger enterprise's home page and other properties is exactly what universal navigation exists to provide in a large, multi-subsite organization.

2 — Global navigation. The support portal's own top-level sections represent the global navigation for this particular subsite — its equivalent of a home page and major sections, scoped to the portal itself.

3 — Local navigation. A sidebar that only appears within Documentation, showing that section's own subsections, is local navigation — it orients someone within one part of the site, not the whole thing.

4 — Contextual navigation. Anchor links jumping to subsections of the single page they're already on is the smallest-scoped type — contextual navigation operating entirely within one page.

The reported confusion between the main corporate site and the support portal is a predictable consequence of universal and global navigation not being visually distinguished from each other. A reasonable fix is giving universal navigation a distinct visual treatment — a different background color, a thinner bar, or placement clearly above and separate from the portal's own header and primary navigation — so users can immediately tell "this bar takes me to the wider company" apart from "this bar takes me around the support portal itself." When both look visually similar or sit too close together, users have no way to tell which system's hierarchy they're navigating at any given moment.
